Why this exists

Everything else truncates. This doesn't.

Mirrored notifications cut answers in half. Voice assistants can't show a code block. Phone apps assume six inches. NiroWear treats the watch as the primary device.

🔌

Four real adapters

OpenAI Responses, Anthropic Messages, Gemini GenerateContent and generic Chat Completions. Protocol follows the provider type — never guessed from a model name.

🔑

Your key, stored properly

AES-GCM under a non-exportable Android Keystore key. Only ciphertext and nonce touch disk. No plaintext fallback, ever.

📱

No typing on the watch

The watch serves a one-time pairing page. Paste the key on your phone into a real form; it arrives encrypted with ephemeral ECDH + AES-GCM.

⌨️

Keyboard and voice

Both are first-class. Voice delegates to the platform recogniser and always returns text you can review before sending.

📖

A reader, not a bubble

Output is parsed into semantic blocks — headings, lists, code, math, tables, links — and rendered as a document.

↔️

Wide content pans

Code and formulas never shrink into illegibility. They pan horizontally inside one vertical reader. Tables become labelled records.

⏹

Stop that actually stops

Stop cancels the HTTP request and keeps the partial answer. Nothing is replayed behind your back.

🧵

One linear conversation

Edit an earlier message: it replaces it, deletes what followed, and regenerates. No branches, no variant pickers.

🕶

No backend at all

No analytics, no crash reporting, no NiroWear server. The only network calls go to the endpoint you configured.

Install

Two minutes, no store

There is no Play Store listing. Sideload the signed release, or build it yourself from source.

Download the releaseGrab the latest .apk from the releases page. It is signed and non-debuggable.
Enable developer options on the watchSettings → System → About → tap Build number seven times, then enable ADB debugging.
Install over ADBConnect the watch by USB or use wireless debugging, then run the command below.
adb install -r NiroWear-0.1.0-beta.5.apk

Upgrading from an older beta keeps your conversations, because the signing identity is unchanged. 

git clone https://github.com/michaelxdips/NiroWear.git
cd NiroWear
.\gradlew.bat :app:assembleDebug
adb install -r app\build\outputs\apk\debug\app-debug.apk

Needs JDK 25 and Android SDK platform 36. The Gradle wrapper is checked in — do not install Gradle separately. 

# On the watch: Settings → Developer options → Wireless debugging → Pair with new device
adb pair 192.168.1.50:37123
adb connect 192.168.1.50:5555
adb install -r NiroWear-0.1.0-beta.5.apk

The IP and port come from the watch's own wireless-debugging screen. Both devices must be on the same network.

Provider setup

Get the key onto the watch without typing it

An API key is 40–200 opaque characters. Typing that on a 1.4-inch keyboard is not a friction problem, it is a correctness problem — the failure mode is a silent typo.

Open Providers / model → Add your providerName and base URL are prefilled. Only the key is missing.
Tap “Set up from phone”The watch shows a URL like http://192.168.1.24:41234/.
Open it on your phone or laptopFill the normal web form and tap Send to watch. The page is valid for two minutes and one use.
The watch saves and validates by itselfModels are listed automatically. Manual entry stays available underneath if you have no Wi-Fi.
Why a URL and a form? Setup happens once. After that the app rides whatever network the watch already has. A one-time pairing that costs a URL is cheap when it is never repeated.

Straight answers

FAQ

Including the limitations, because a page that hides them is useless.

Where is my API key stored?
Encrypted with AES-GCM under a non-exportable Android Keystore key. Only versioned ciphertext and a nonce are written to storage; the provider profile holds a credential reference, never the key. If decryption fails you must re-enter it — there is deliberately no plaintext fallback.
Does it work without a phone?
Yes. NiroWear is a standalone Wear app. The phone is only convenient for pasting the key during setup, because it has a real keyboard. It needs its own network — Wi-Fi, or the Bluetooth bridge if a phone is paired.
Is my conversation sent anywhere else?
No. There is no NiroWear backend, no analytics and no crash reporting. Requests go directly from the watch to the endpoint you configured, so that provider's retention policy applies — not ours.
Why isn't native math typesetting in release builds?
The native renderer depends on a GPL-with-linking-exception library whose exact redistribution obligations are not cleared. Release builds use a source fallback: LaTeX stays readable and pannable, but it is not typeset. The native path exists in debug only.
What still isn't verified?
Physical Xiaomi Watch 2 acceptance (battery, thermals, input), voice transcription accuracy, end-to-end link taps on a paired device, and TalkBack audio. Emulator evidence is extensive; it is not a substitute for a real watch.
Can I use any OpenAI-compatible endpoint?
Yes, as long as it speaks Chat Completions over HTTPS and you know a model ID. Model discovery failing never blocks you — type the model ID manually. Discovery and authentication are separate checks.
Will switching provider lose my history?
No. History is provider-neutral; each assistant message records which profile and model produced it, so one linear conversation survives any number of switches.
Is there an iOS-paired story?
The pairing page works from any browser, including an iPhone, because it is just a URL on your LAN. No companion app is involved on either platform.
