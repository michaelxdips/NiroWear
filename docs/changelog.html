0.2.0 2026-11-08 Latest

Nothing is withheld from a long answer

A table was one lazy item capped at 40 rows, and a code fence was a single text node holding the whole fence. Both were the jank the cap was meant to prevent, and both contradicted the rule that an answer is never shortened for the screen. Every table row and every 24-line code chunk is its own item now, so the cap is gone rather than raised.

  • Eight product bugs fixed. Stop no longer downgrades an answer that had already finished; Retry with no user message refuses instead of blaming the provider; a terminal chunk that carries only finish_reason no longer fails a complete answer; a bare Gemini host resolves to /v1beta instead of 404ing; pairing stops delivering a payload after Cancel; an accepted socket is closed when the handler thread cannot start; one transient DataStore error no longer strands the provider screen; and the dropped-cells notice is reachable again.
  • The pairing listener accepts the browser behind a hostile peer. Each request is joined with a hard time bound, which blocks the accept loop by design — with a listen backlog of 1, a peer that filled the single queue slot made the real connection fail with ECONNREFUSED. Measured as a ConnectException in the JVM suite. The backlog is 8.
  • Four accessibility dead stops removed: the Links group opens the first link instead of announcing a count it could not activate, the composer field carries its own label, a credential label is no longer announced twice, and the provider header survives a 2.0x font scale.
  • The whole UI is localised: 89 strings moved into resources with a complete Indonesian set; technical terms stay English, and every English value is byte-identical to the literal it replaced.
  • Nothing freezes the dial on input: pairing key generation, certificate minting and the listener bind left onClick, the close-path join left the caller, and discovery gained a 30 s whole-operation budget.
  • Smaller and bounded: math layout capped at 16384 × 1024 px and 3,000,000 px area, list depth at 4, memoised inline nodes, and 1.20 MB of dead Markdown artifacts deleted with the documentation tree cut from 1.4 MB to 285 KB.

0.1.2 2026-11-07

Validate is advisory; Save is not gated on a live call

Save used to stay disabled until a real API call succeeded, which made the app unusable offline, behind a captive portal, or while a provider was briefly down — and contradicted the same screen's "chat still allowed" message. Save now needs the data a profile needs, and an unvalidated save says so on screen.

  • Save requires name, base URL, model and a key (or an existing profile) — not a successful live call. The first send reports a bad key as an error row on the conversation.
  • Validate and Discover are unchanged: Validate still makes one real call, Discover still lists what the provider advertises, and discovery failure still never blocks manual entry.
  • Instrumentation executed for the first time. The published "48 / 48" was never reproducible: the suite is 66 methods. Measured 66 / 31 failing at the start of the audit, 66 / 18 at this release; the remaining 18 were itemised in the README. An earlier revision said "14" — that number was inferred from a partial run, not measured, and was wrong: the tests share one app process, so a class that passes alone can fail in suite order. Test-side fixes afterwards (fixture cleanup, stale mock queues, impossible geometry assertions, bidi-mojibake literals, and a History list offset the composable discarded on every close) brought the measured figure to 66 / 2.

0.1.1 2026-11-06

Fixes only — and the first automated signed release

No new product surface. The release is built and signed by .github/workflows/release.yml from the tag, under a dedicated release key, so the artifact and its certificate no longer depend on the machine that cut it.

  • A Keystore hiccup no longer destroys every saved key. A transient failure while obtaining the key used to delete the shared entry, permanently orphaning every other provider's ciphertext. Obtaining the key is now its own failure domain; only a key that genuinely cannot encrypt is replaced.
  • A failed turn recovers instead of vanishing. A Stop or error after an edit or retry had already written records a STOPPED/ERROR row (it used to delete the previous answer with no row, no status line and no Retry); a Stop inside a new chat's first insert keeps the typed prompt; a refused edit re-opens the editor with your text.
  • Provider truth. A long reasoning phase is no longer killed as "Provider timed out"; a cut answer from pause_turn or tool_use is disclosed; "Partial answer kept." appears only when text survived; a captive-portal page is reported as unreachable; non-2xx bodies are read for Anthropic, OpenAI and compatible gateways; Anthropic model metadata is cached per endpoint and model instead of fetched on every send.
  • Renderer. A table inside a list reports the cells it had to clamp, a $$ in a table row no longer shreds the table, an HTML block no longer steals the next table's notice, a prose line with backticks is not a fence, and spacing commands such as \hspace typeset instead of degrading to source.
  • Signing identity changed. 0.1.0 used the Android debug lineage; 0.1.1 uses CN=NiroWear Release. A 0.1.0 install must be uninstalled before updating — that removes local conversations and saved keys.

beta.7 2026-11-02

Finish campaign: renderer, hardening, watch-frame demo

beta.6 2026-10-22

Native LaTeX in release builds

Until this release, release builds could only show formula source as monospace text. The debug-only stub returned null and the reader fell back to the LaTeX source. Both variants now share one native typesetter.

  • Licensing resolved on evidence. The dependency's POM declares plain GPL v2; its actual LICENSE carries an independent-module linking exception, which is what permits linking it from MIT code.
  • Obligations shipped. The notice, the exception and the canonical GPL-2.0 text are bundled in the app under assets/legal/.
  • Hostile input refused before the parser sees it. File-inclusion macros, macro definitions and unbalanced braces degrade to readable source; a refused formula never renders blank.

beta.5 2026-10-22

The credential-entry release

Setting up a provider stopped requiring a 164-character key typed on a watch keyboard. The watch serves a one-time page; the key is pasted on a device with a real keyboard and encrypted before it leaves the browser.

  • Ephemeral ECDH P-256 + AES-GCM, with a 128-bit single-use token as associated data.
  • Two-minute TTL, one use. The socket closes when you leave the screen.
  • Errors that name the actual problem. A 401 reads “API key rejected”; a 404 reads “Model unavailable”. They were previously one message.
  • Source published under MIT at github.com/michaelxdips/NiroWear.
